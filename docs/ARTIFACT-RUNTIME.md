# Offline visual artifacts

Brown can request an `artifact` specification containing a title, `svg` or `html` format, and self-contained source from the selected local visual model. Custom illustrations, posters, layouts, timelines and relationship drawings use the same runtime; no subject-specific renderer is required. Structured chart, sequence, flowchart and geometry renderers remain available.

The source follows the existing local generation lifecycle, cancellation and shared recovery budget. Invalid specifications and malformed SVG return concrete errors for bounded repair. A static artifact cannot execute JavaScript, access files or perform external actions. Unsupported interactive requests still need an appropriate execution capability.

Each preview uses an opaque-origin sandbox. Generated scripts remain forbidden; a nonce permits only Brown's fixed fitting script. Networking, forms, nested frames and external resources remain blocked, including in expanded previews. The fitting script measures SVG bounds, expands an undersized viewBox, scales oversized HTML to the viewport, and reports height through source-and-channel-checked messages. A bounded layout inspection can return severe label collisions for repair. Source remains size- and element-limited. These checks do not verify every visual relationship or factual claim.

Illustrations have a thin white outline around the preview and controls, without a title bar. Code, Copy, Export, Expand and Revise sit above the preview, aligned right. A blue BETA badge sits left, beside an info button with the sidebar subitem surface. Hover or click opens a small experimental-status popover; click pins it, while another click, Escape or an outside click dismisses it. The popover is removed when its illustration unmounts. Diagram and chart renderers do not receive this illustration badge. Code opens a dedicated right-side source panel with a rounded title pill and temporarily hides the session rail, preserving its state. The illustration stays visible; there is no inline code block or extra copy-code bar. Exports contain prepared SVG or a restricted standalone HTML document. Artifacts persist in the response's source fence and render when a chat reopens. The Outputs section includes these artifacts with their titles. Older generic widgets remain a separate feature.

Visual revisions resolve the preceding same-chat request, including corrections from source code to an HTML/CSS mockup. Relevant earlier answers are passed to the visual generator with a bounded context budget. Explicit UI mockups use the artifact renderer rather than becoming login flowcharts. Static mockups cannot submit forms or run application logic.

The design playbook emphasizes a dominant recognizable subject, balanced typography, surrounding labels and a compact supporting section. Placeholder acknowledgments are rejected for bounded repair. Preview inspection detects low text contrast as well as SVG label collisions. HTML body palette styles survive sanitization, and default text no longer inherits white from the dark application theme. These safeguards improve legibility but do not guarantee factual accuracy or aesthetic quality.

Visual model selection favors installed text/code-capable models with memory headroom and avoids treating vision support as a requirement for writing SVG or HTML. Small models remain a fallback on constrained machines. No model is downloaded automatically; insufficient RAM and weak model output can still limit quality and speed.

The source panel tracks the chat area's top and height with a ResizeObserver. Its independently scrollable code region contains escaped HTML/SVG syntax spans and supports keyboard scrolling; opening and closing respect reduced-motion preferences. On Windows the panel and its descendants explicitly opt out of the draggable window region, allowing wheel input and text selection. The Electron test checks native wheel scrolling in both directions with Windows styling enabled. Generation statuses show a real elapsed clock and a rounded surface using the same background token as sidebar subitems. A soft diagonal CSS wave sweeps across the surface; no canvas, frame loop or external dependency is required. Reduced motion disables the wave. The surface enters with a short fade/lift and fades out independently when replaced, without delaying result completion. The placeholder is indeterminate, not a claimed percentage or a partially generated image.

Explicit standalone artifact requests skip the redundant interpretation inference. Contextual requests and requests involving files still use interpretation. `illustration-design.js` supplies reusable composition, shape, curve, typography and compact-source guidance in the generation call itself. The stable design prompt prefix permits local prompt-cache reuse. Trace entries record first-token latency and Ollama loading, prompt evaluation and generation metrics. Status text follows real startup, source generation, validation, layout checking and repair events, rather than pretending elapsed time indicates a completed design phase.

Verify with `tests/artifact-runtime-electron.test.js`, `tests/visual-planner.test.js`, `tests/request-pipeline.test.js`, and the normal `npm test` suite. Small local models may still fail to produce a usable artifact within the retry budget. No cloud generation is added.
