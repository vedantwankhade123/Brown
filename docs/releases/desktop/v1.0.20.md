# Brown AI Desktop 1.0.20 — local conversation reliability

This local build consolidates the reliability work from the current workspace. It has not been published to GitHub or installed over the user's profile.

## Changes

- Shared local inference adapter for chat generation, structured interpretation/evaluation, visual generation, legacy renderer requests and the floating bar.
- Cached model capability discovery, context-window limits and model-supported reasoning defaults for ordinary answers; conservative fallback when metadata is unavailable.
- Explicit request lifecycle transitions and bounded recovery, preserving cancellation and cleanup.
- Short language follow-ups reuse the preceding answer directly. Generation prompts contain concise instructions rather than interpreter-generated goal JSON.
- Markdown-fenced comparison tables are normalized before checking and rendering. Table width/data-row checks remain active.
- Repetitive-stream detection, correction context, incomplete-output recovery and clearly labelled unsuccessful repairs.
- Hardware-aware chat concurrency up to five; profile/data isolation safeguards and runtime diagnostics from the preceding workspace work.

## Verification and interpretation

The automated regression suite, Electron chat integration and edit/regenerate tests pass. The packaged executable can be tested with `--brown-smoke-test`; it uses an ephemeral profile, a synthetic greeting and no normal application boot. Set `BROWN_SMOKE_MODEL` to an installed model and `BROWN_SMOKE_REPORT` to the output JSON path.

`scripts/evaluate-local-chat.cjs` runs synthetic fixtures against the local Ollama server directly, Brown's source executor, or an executor loaded from a packaged app.asar. It does not read real chats. Reports record output, timing and request metadata. Structural smoke checks are not proof of semantic correctness; manually reviewed failures are retained in the reports.

Live LLaVA testing reproduced the broken one-column comparison without Brown. Brown's correction path produced a multi-column result. Live Phi-3 testing exposed a valid fenced table that Brown incorrectly rejected; normalization fixes that case. Both models produced inadequate Marathi text on manual review, even when basic script checks passed. The installed Gemma model produced a coherent Marathi version of the test joke both directly and through Brown. This is a small sample, not a general model certification.

No model downloads or cloud inference are required for these tests. Ollama remains a shared local service. The smoke test does not establish that all production-profile configurations, all tools, all models, or translations work correctly.
