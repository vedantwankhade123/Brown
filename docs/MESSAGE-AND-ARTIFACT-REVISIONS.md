# Message edits, artifact revisions and source evidence

User messages have an **Edit message** action. It edits the bubble inline, hiding its normal actions and showing **Cancel** and **Send**. Cancel or Escape restores the original bubble without changing history. Ctrl/Command+Enter sends; Enter inserts a new line. Sending an edit archives only that request and its answer, then replaces that turn in place. Assistant messages have **Regenerate response**, which archives and replaces only the selected answer. Later messages and illustrations stay visible throughout generation and after completion. Model history includes only messages before the selected request, so later answers cannot leak into its context. Empty edits and duplicate submissions are blocked. Regeneration reuses the preceding user request without adding a duplicate user message. The currently selected chat model is used.

Where an earlier version exists, **Saved versions** opens its preview and a restore action. New snapshots are scoped to one turn; restoring them preserves all later messages and archives the current turn when needed, so the switch is reversible. Legacy snapshots retain their original whole-branch restore behavior for compatibility. Restoring identical current content is a no-op. Equality compares message content, attachments, evidence, request context, snapshot scope and the conversation prefix; timestamps, job identifiers and snapshot labels do not create new versions. Existing duplicate snapshots are consolidated when a chat loads or its history opens. A hash narrows candidate comparisons, followed by exact canonical-content equality so collisions cannot discard content.

**Delete version** opens an inline confirmation before removing that saved snapshot. Current messages and other versions are preserved. Versions without generated output show a disabled **No result to restore** action, while deletion remains available. Empty responses, unfinished jobs, failures, and legacy timeout/interruption notices are excluded by the restore operation as well as the UI. Stopped responses with actual partial content remain eligible. The list indicates which snapshot matches the current conversation and how many messages each version contains. Branches are stored with the chat on disk. A prefix check prevents restoring a response into an unrelated conversation branch. Stop the selected chat's running request before editing or restoring it; jobs in other chats can continue.

New requests retain their document prompt context, file references and knowledge scope for retries. Existing saved attachments and images are reused. Older messages that never saved document context or image data require the attachment again; Brown does not silently regenerate a file answer without its file.

Illustration controls include **Revise**. It attaches the selected illustration as a removable reference chip in the main composer and focuses that input without replacing a draft or sending anything. Type the changes, such as moving a label or changing a color, then use normal Send. References stay scoped to their chat, clear after successful submission, and are marked on the saved user message. The request includes the selected illustration's complete source and asks the local model to preserve its subject, values and unaffected layout. The result appears as a new answer; the earlier artwork remains available. This is model-based source revision, not a guarantee that every unaffected pixel stays identical. Large sources that exceed the available context budget return a limitation instead of silently truncating the original.

Click a retrieved-source chip to open **Source excerpts**. The viewer shows saved excerpts associated with that answer, including indexed-excerpt numbers where available. **Read current indexed file** loads the current locally extracted text and highlights an exact match with line positions. These are positions in extracted text, not asserted PDF page numbers. If no verbatim match is found, the saved excerpt remains visible and the viewer explains that the preview may be incomplete, extraction formatting may differ, or the source may have changed. A citation identifies retrieved evidence; it does not prove every generated claim.

Verification: `node tests/message-workflows.test.js`, `electron tests/message-workflows-electron.test.js`, existing background-job tests, and the normal test suite.

Conversation generation normalizes legacy message roles and reserves space for the latest exchange before older referenced material. It honors an interpreted independent request's `useContext:false` instead of carrying stale tasks into every answer. Failed/status-only responses are excluded from generation history. Available capabilities come from the shared registry; disabled computer execution does not imply that writing, explanations or other chat assistance are unavailable. The provider adapter deduplicates only a matching final user message, so a repeated greeting earlier in history cannot suppress the current request.

Text fulfillment checks include greetings and interpreter fallbacks, detect application-plan echoes, and semantically recheck the one permitted correction. Correction feedback accompanies the final user request instead of relying only on earlier system instructions. Semantic verification remains model-dependent: invalid or unavailable checker output is recorded as unchecked, not treated as proof of correctness. Very small local models can still misunderstand requests or fail both interpretation and verification. Trace messages include job/chat identity, model, history role/length order and timing without logging full message bodies. `tests/conversation-fulfillment.test.js` covers latest-turn payloads, role normalization, capability grounding, stale-task isolation and bounded repairs with deterministic model fixtures.
